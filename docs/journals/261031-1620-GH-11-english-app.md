# English Copy Translation for the Judge Demo

**Date**: 2026-10-31 16:24
**Severity**: Low
**Component**: ReturnOps UI, demo fixtures, client errors, agent prompt
**Status**: Resolved

## What Happened

The app was still presenting Vietnamese copy across the queue, evidence review, owner controls, timeline, errors, accessibility labels, metadata, and seeded demo requests. That made the judge-facing flow inaccessible to the intended international audience. The copy was translated in place and the browser test locators were updated to follow the new labels.

## Technical Details

The main surface was `src/features/returnops/returnops-app.tsx`; supporting copy lived in `api.ts`, `presentation.ts`, `test-adapter.ts`, `demo-reset.ts`, and `app/layout.tsx`. Dates now use `en-GB`; VND currency and domain identifiers remain unchanged. The agent instruction explicitly requires English replies and escalation reasons. Root tests passed 44/44 and the test package passed 14/14, including desktop 1280px and mobile 390px coverage. Typecheck, lint, and build passed; lint has one pre-existing warning and build has a non-blocking punycode warning.

## Decision and Lesson

We replaced copy in existing modules instead of introducing a localization framework because this is a single-language judge demo and the acceptance requirement is English output now. Persisted user-authored records remain untouched; only app-owned defaults and synthetic fixtures changed. Future copy changes need a repo-wide scan of source, fixtures, API fallbacks, and test selectors before calling the UI translated.

## Next Steps

Run UI-local against the designated disposable target once its mutation opt-in and adapter are configured. Existing persisted D1 records can still contain Vietnamese until an explicit demo reset after deployment; do not reset shared state as part of this translation task.
